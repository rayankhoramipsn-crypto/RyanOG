# TRISOCMD additive staging migrations

`20261030193709_marketplace_private_gallery.sql` was applied only to staging
project `cxtytbjvdlngahytfilr`. The filename matches the recorded remote migration
version. It was initially generated by `supabase migration new`, then aligned to
the version assigned by the remote migration API.

This repository previously did not contain the baseline database migrations.
The new migration requires the existing `market_listings`, Auth, Storage, and
`public.is_admin()` foundation. It is **not** a complete database bootstrap.
Do not reapply to staging or run against production. A production rollout needs
an audited baseline, backup, explicit approval, and a migration plan.

The private `market-gallery` bucket accepts JPEG, PNG, WebP, up to 5 MiB each.
A listing can have six media rows, enforced with unique positions 0–5.
Pending media is visible to the owner and admins; approved media is public via
five-minute signed URLs. Sellers cannot insert/delete media after approval.
Existing signed URLs can remain usable until their five-minute expiry after a
moderation change or removal. Uploaded files are not scanned for prohibited
content; moderation is manual. Storage abuse quotas/rate limits and orphan cleanup
are operational follow-ups before production.

Run the rolled-back role test `tests/staging_gallery_rls.sql` only on staging.
It simulates JWT claims at the SQL role boundary, not a real HTTP login/Storage
upload. Never store database passwords or privileged keys in this repository.
