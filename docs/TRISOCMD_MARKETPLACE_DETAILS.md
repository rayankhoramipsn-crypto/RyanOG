# Marketplace listing details — focused staging update

The reference was used only for layout/style. No reference image, sample listing, sample price or media was copied into application files, Storage or hosted records. All title/platform/description/price/media come from the selected listing; the seller name is read only through the existing public-profile RPC. No ratings, condition, video thumbnails or synthetic listings are invented. Fixture data/images remain in tests and ignored local screenshots only.

Main/preview use the same dark violet/cyan two-column detail layout, responsive gallery, real thumbnails, previous/next controls, keyboard arrows, nested fullscreen, missing/failed-media states, compact scrollable rules, explicit purchase consent and separate chat/purchase actions. Dialog scrolling stays contained. EN/FA/AR labels and directions are preserved. A real 768px navigation overflow was found in rendered RTL screenshots and fixed by adapting desktop navigation at the tablet breakpoint; page-width assertions now cover it.

Chat uses `market_start_chat(p_listing)` and the existing inbox/history/Realtime/polling/idempotent-send infrastructure. It no longer requires purchase consent or a purchase request. Self-chat is rejected, duplicate clicks are coalesced, and returned threads must include the current participant. Session changes clear private chat and invalidate late action responses. Signed-out actions retain only a recent listing ID/action/preview flag in sessionStorage, never credentials. Existing email login resumes the intent; an explicitly requested main/Google sign-in handoff returns to the same listing through a small UI adapter, without changing Auth/provider APIs.

Both Buy from Chat and the detail shortcut return to the same listing purchase controls and require explicit rules acceptance. Continue refreshes the active session, rereads the approved listing/price and rejects changed availability; a changed price resets consent for review. The existing `market_request_purchase` is created/reused with `CONTACT_SUPPORT`, then the existing idempotent `phase1_market_order` links/reuses the canonical order. Existing saved requests retain their original amount, which is displayed on the next step. No listing is marked sold and no payment or payout is initiated.

`marketplace-checkout.html` is a dedicated canonical-order review step, not another order system. It uses an owner-filtered `TrisoOrders.get()` read, clears stale data on account changes, shows actual stored amount/status and offers back/support/refresh. Payment method belongs here and is explicitly unavailable/disabled on staging. This step makes no financial Edge Function calls and displays no wallet address or pretend gateway.

Existing static tests were updated for the moved selector, current cache revisions and already-implemented language persistence. Live role/chat/Storage/Realtime and a real Google return still require dedicated staging-account acceptance; fixtures do not verify hosted behavior. Hosted RPC definitions were inspected read-only, without business rows. No hosted migrations, production, provider activation, avatar changes or notification-onboarding changes.
